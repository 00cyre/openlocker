# Keep your place through updates

- Protected websites are saved with a profile-local recovery copy. A missing list can recover from that copy or existing protection rules instead of silently clearing the rules.
- Locked tabs are remembered continuously, including duplicate URLs, positions, pinned state, and their windows. The Update button keeps them in place while reloading; manual Chrome reloads restore lock pages that Chrome closes.
- A failed update, ordinary worker restart, or deliberately closed tab does not turn into duplicate/restored tabs. Recovery never unlocks a protected site.
- Mac updates checkpoint running protected apps and leave their processes/windows untouched. If a protected app goes missing during the handoff, the new locker can reopen its validated bundle. The installer also supports recovery when upgrading an older OpenLocker version.
- Only OpenLocker restarts. Protected app settings survive, and fresh Touch ID is still required after restart. The five-minute inactivity behavior from 0.1.5 remains.

Validation: extension regression tests reproduce missing reload tabs and destructive startup recovery before the fix, then verify restoration and settings retention. Swift recovery, installer, signing, and native-messaging checks cover the Mac update. A local two-window AppKit fixture preserved its PID, window IDs, visibility, and unsaved text across real installer transactions and a blur-process restart. The native app-closing report was not reproduced in that fixture; the recovery handoff adds protection against losing running apps. Live Chrome reload and physical Touch ID checks remain interactive.

Already-lost tabs/settings without a surviving record cannot be reconstructed by this version. The continuous journal protects subsequent reloads after 0.1.6 has first run. Existing Chrome lock pages may close once when reloading an older version; keep their destinations before that first upgrade. Do not remove/re-add the extension to update it.
