Fixes the repeated Touch ID prompt after a successful website unlock, including sites on `127.0.0.1`.

The temporary allow rule previously omitted its resource-type filter. Chrome's default excludes the main page request, so authentication succeeded but the next navigation was redirected straight back to the lock screen. The allow rule now explicitly includes the page and its resources while remaining limited to the authenticated tab and protected domain. Other tabs remain locked, and switching tabs or locking again still revokes access.

Validation: a navigation regression reproduced the redirect loop before the fix and passes afterward; the extension suite also checks cancellation, tab isolation, relocking, and focus changes. The navigation test models Chrome's documented matching defaults. Physical Touch ID and the final loaded Chrome state require local user verification.

From 0.1.2, use **Check for updates** in the extension to download this release and reload automatically. The Mac app's update includes the corrected extension in its bundled Chrome installer. This release retains the persistent signing identity used since 0.1.1.
