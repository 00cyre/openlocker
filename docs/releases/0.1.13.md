# Automatic Mac app updates

- Enable **Automatically install updates** in the Mac menu. OpenLocker checks at launch and every six hours, then installs a verified newer release after five minutes of Mac inactivity. The option is off until enabled.
- Automatic updates need no Touch ID prompt. They wait for authentication, setup, app selection, menus, and modal dialogs to finish. Returning to the Mac or disabling the option during the download cancels that installation attempt.
- Updates preserve protected-app settings and use the existing open-app recovery transaction. Only OpenLocker restarts. The matching Chrome helper and extension files are installed too; the extension's reload reminder and **Open extension settings** button remain available.
- Automatic relaunches stay quiet. Download or verification failures retry after an hour; installation failures restore the previous app and apply the same delay. Manual updates remain available with Touch ID.

Validation: deterministic tests cover opt-in, newer-release gating, the exact idle boundary, invalid timing, interaction deferral, eligibility changes during downloads, and retry delays. Existing Mac policy, post-Touch-ID focus, recovery, extension, installer, signed-update, and native messaging checks remain required. The updater never grants access to protected apps or carries fingerprint grants across restarts.

Install 0.1.13 once through the existing update button, then enable the new menu option for future releases. Chrome still requires **Reload** to activate newly installed extension files.
