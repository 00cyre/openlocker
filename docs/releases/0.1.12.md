# Keep successful unlocks when window focus changes

OpenLocker used to revoke a successful Touch ID unlock if macOS declined its subsequent request to bring the app forward. That could immediately cover the app again and open another modal during a competing focus transition.

Bringing the window forward is now best effort. A declined focus request preserves the authenticated, process-specific unlock and opens no extra modal. The app still relocks after five minutes without use, on manual locking, and when the Mac sleeps or locks. Protected app and website lists are preserved.

Validation: a deterministic regression executes the production post-authentication method against the real lock policy, substituting only the macOS window effects. It reproduces the immediate relock before the fix and passes afterward for both accepted and declined focus requests. It also checks five-minute expiry, window restoration, stale authentication, terminated processes, and mismatched app identities. The reported Claude/OpenComputer interaction still needs confirmation with physical Touch ID after updating.

Update from the Mac menu with Touch ID. The matching Chrome extension files are included; use **Open extension settings** and click **Reload** to activate them. Chrome locking behavior is unchanged in this release.
