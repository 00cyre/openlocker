OpenLocker now brings up Touch ID automatically when you open a locked website or Mac app, and includes update controls in both products.

- Fixed a successful website unlock being rejected when the system Touch ID dialog returned focus to the same Chrome tab. Actual tab changes and navigation still invalidate the pending unlock.
- Touch ID opens automatically for a visible locked tab or newly opened app lock. Cancelling leaves a retry button; focus changes do not cause a prompt loop.
- **Mac app → Install Chrome extension…** installs the bundled helper and prepares the extension folder, then guides you through Chrome's required initial approval. No Terminal or separate download is needed.
- The Mac app checks on launch and every six hours. Its menu offers **Update to…** and installs/relaunches after verifying the release signature. Touch ID confirms an update if apps are protected.
- The extension checks when its popup/settings opens (cached for an hour). **Update to…** installs through the native helper and reloads Chrome's extension while keeping its domain settings. Chrome-only updates never replace the running Mac app.
- Downloaded disk images are checked against the persistent release certificate before mounting. Installer signatures and versions are checked again before execution. Downgrades, unexpected assets, tampering, and concurrent installations are rejected.

**One-time setup for older versions:** install 0.1.2 using the DMG. If you loaded the repository's `extension/` folder, use **Install Chrome extension…** in the Mac app and load the prepared folder at `~/Library/Application Support/OpenLocker/extension` in Chrome. Do not uninstall the existing extension to migrate. Future updates use the in-product buttons. Chrome still requires **Load unpacked** once because this extension is not in the Chrome Web Store.

Update checks contact GitHub for release metadata; downloads happen when you request an update. Protected domains, apps, and biometric data are not sent. The release uses the same self-signed identity as 0.1.1; it is not Apple-notarized.

Validation includes extension focus-race and automatic-prompt tests, signed-image tampering checks, scoped installer/rollback checks, a real verified download/staging run, universal Swift builds, and native messaging tests. Physical Touch ID and Chrome's initial loading step need local user interaction.
