# Recognizable tabs, quieter switching

- Locked Chrome tabs retain their saved page title and use Chrome’s stored site icon. Titles survive reloads, updates, and restored tab IDs, including duplicate destinations.
- Touch ID starts when you click, type, or scroll inside a locked page. Opening the page, switching tabs, returning to Chrome, and moving the pointer do not prompt.
- Browser shortcuts and Manage protected sites stay quiet. Cancelling does not create a focus loop, and one trackpad scroll burst produces at most one prompt.
- Five-minute idle sessions are unchanged. An already-unlocked domain resumes without another fingerprint. Mac app prompts and update recovery are unchanged.
- Titles are kept locally for currently open protected tabs and are not sent to the helper or GitHub. The favicon permission is covered by the existing tabs permission.

Tabs locked before this release have no saved original title; they show their domain and path until unlocked once. Chrome may show its default icon if it has no stored favicon. Keep the extension installed when updating so protected sites and tab recovery records survive.

Validation: regression tests exercise the real lock-page script with focus/input events and the background worker through locking, title changes, cancellation, duplicate-tab restoration, and reload. The release also runs the existing Mac policy, native protocol, installer, signature continuity, and update recovery checks. Physical Touch ID acceptance remains an interactive check.
