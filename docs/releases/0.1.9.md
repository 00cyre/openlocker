# Five minutes per app and website

Each protected Mac app and website now has its own five-minute inactivity timer. Using another app or website no longer keeps it unlocked.

- Returning before five minutes or interacting with an unlocked app or site renews only its timer. Website timers are shared across tabs for the same unlocked domain.
- Returning after expiry requires Touch ID again. Websites still wait for deliberate input in the lock page before prompting; switching tabs alone never starts authentication.
- Chrome schedules each domain's expiry even while you work elsewhere. Open protected pages also check their deadline, and worker restarts retain the remaining time. Chrome can delay background alarms; returning to an expired page still requires authentication.
- The Mac app renews only the foreground app when input occurs, and checks each app's deadline independently. It reads input timing, not key contents.
- Protected lists, original tab destinations, titles, icons, and app update recovery are preserved. Updates relock access without closing protected apps.

Validation: 74 JavaScript tests, including independent site expiry while other input continues, target-only renewal, inactive-window rejection, missed alarms, worker restarts, and a document deadline fallback. Swift policy tests cover independent app expiry, renewal before the deadline, rejection after it, and polling without input. The release workflow also checks Mac activation, accessibility identity continuity, update recovery, installer behavior, signatures, and the native protocol. Physical Touch ID and the installed six-minute interaction check remain manual acceptance steps.
